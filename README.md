## Зафиксированный логотип

Мастер v1: `design/logo-master/master.png` — прозрачный RGBA PNG,
полученный программным удалением бумаги из утверждённого рисунка.
`design/logo-approved-paper.png` сохраняет исходник с подложкой.
Рисунок генератором повторно не создавался.

В `design/logo-master/` лежат три точных слоя: `illustration.png`,
`wordmark.png`, `tagline.png`, их координаты в `layers.json` и контрольные
суммы в `sha256.json`. `master.svg` — редактируемый контейнер с растровыми
альфа-масками (не векторная трассировка); группы illustration, wordmark,
tagline можно скрывать и перекрашивать, background — включить.

Правила работы с мастером закреплены в AGENTS.md. Для экспорта нужен Pillow:

```sh
python3 scripts/logo.py --color '#354453' --output design/exports/blue.png
python3 scripts/logo.py --hide wordmark tagline --output design/exports/illustration.png
python3 scripts/logo.py --background '#f8f9fa' --width 1600 --output design/exports/on-paper.png
```

Скрипт проверяет хеши мастера перед экспортом и запрещает запись внутрь
его каталога. Штатные изменения делаем только в производных файлах.
Это защита от случайных изменений, а не внешняя система контроля доступа.
Рекомендуется хранить мастер вместе с проектом в Git и отметить принятую
версию тегом. Точная векторизация остаётся отдельной задачей. С 20.09.2026 подпись
«Журнал обыкновенных невероятностей» набрана локальным PT Sans: в правой колонке шапки и один раз на отдельной OG-карточке главной.
На OG-карточках статей подзаголовок отсутствует. Старый слой
tagline сохранён только в архивном мастере v1. Утверждённая палитра: #35312F и #FAF8F3.

Отдельный новый блог на Hugo. Старый репозиторий и maks.live не изменены.
Сборка проверена с Hugo 0.166.0. Не требует Node.js, Python или Go toolchain
для обычного запуска: достаточно готового бинарника Hugo. Python 3 и зависимости tools/requirements-build.txt нужны для сборки и календарей.

## Запуск

Установить Hugo версии из `.hugo-version` (https://gohugo.io/installation/).

```sh
git submodule update --init --recursive
python3 -m pip install -r tools/requirements-build.txt
make dev                  # предпросмотр с черновиками, localhost:1313
hugo new content posts/my-note/index.md
make build                # публичная сборка в public/, без черновиков
make check                # сборка и проверка метаданных/ресурсов
```

`make preview` создаёт отдельную сборку с черновиками в `preview/`.
Для просмотра: `python3 -m http.server 8765 --directory preview`.
Все страницы режима preview получают noindex. Это не защита доступа:
черновики не следует выкладывать по публичному адресу.

## Как писать

Каждая публикация — папка `content/posts/slug/`: `index.md` и фотографии.
Пример метаданных:

```yaml
---
title: "Название записи"
date: 2026-09-14T18:00:00+03:00
description: "Описание на одно-два предложения."
kind: "Заметка"
draft: true
cover: "photo.jpg"
cover_alt: "Что изображено на фотографии"
---
```

Картинка в тексте: `![Описание](photo.jpg)`. JPEG/PNG/WebP обрабатываются
при сборке в варианты 720 и 1440 px; srcset подбирает размер на устройстве.
Для SVG/видео нужна отдельная обработка, это ещё не готовая медиабиблиотека.

Для публикации убрать `draft: true` или заменить на false. Дата в будущем
также исключает запись из обычной сборки. Черновики в публичном Git остаются
видны в исходниках, хотя не попадают на сайт.

Опубликованные записи: «Квадратная пицца по рецепту из детства»
(`/posts/pizza/`, 13.09.2026), «Русская тропа: 111 километров полей и бродов»
(`/posts/russian-trail/`, 21.08.2025) и «Не пошёл бегать, потому что…»
(`/posts/not-running/`, 31.10.2025).

## Социальные превью

В готовом HTML: Open Graph, Twitter Cards, canonical, описание, даты,
JSON-LD BlogPosting. RSS и sitemap создаёт Hugo.

Без отдельной картинки Hugo автоматически создаёт PNG 1200×630 с заголовком
и знаком. Шрифты при генерации настоящие: Literata и PT Sans.
Можно задать `social_title` (включая переносы строк), `social_description`,
`social_image` (имя файла рядом с index.md) и `social_image_alt`.
Основная `cover` отвечает за картинку в статье; `social_image` — за отдельную
картинку ссылки. Слишком длинный заголовок карточки требует короткого
social_title, сборка ограничивает его четырьмя строками.

Recipe JSON-LD пока не добавлен. Есть BlogPosting; не выдумывать точные массы, время подготовки, калории и порции ради разметки. Реальные превью VK/Telegram ещё не проверены:
нужен публичный URL. Локально проверены наличие тегов и доступность файлов.

## Оформление и решения

- Literata для текста и заголовков, PT Sans для подписей и навигации.
- WOFF2 включены в проект, внешних запросов шрифтов нет. Лицензии OFL —
  `static/fonts/`. Исходные TTF и статическое начертание для карточек — assets.
- Используется утверждённый полный знак без сухого края и штриховки букв.
  Мелкая подпись внутри этой растровой картинки пока нарисована;
  замена её на настоящий PT Sans относится к чистовой подготовке логотипа.
- Утверждены тёплый чернильный #35312F и светлая бумага #FAF8F3.
- Комментариев и аналитики нет. Ссылку для обратной связи можно добавить
  через params.contact; пока она пуста, блок не выводится.
- Новый блог работает на brodov.net. Архив старых материалов и перенаправления — позже.

## Почему Hugo и где нужен Go

Писать статьи — Markdown/YAML. Менять вид — HTML/CSS и Go templates.
Программировать на Go для этого не нужно. Hugo не имеет такого API Python-
плагинов, как Pelican. Нестандартные преобразования можно делать внешними
скриптами, например на Python. Поэтому выбор Hugo пока проверяется прототипом:
если Jinja/Python удобнее для самостоятельной поддержки, Pelican остаётся
разумной альтернативой. Содержимое, шрифты и дизайн переносимы.

Документация: https://gohugo.io/content-management/page-bundles/
https://gohugo.io/content-management/image-processing/
https://gohugo.io/functions/images/text/

## Карты маршрутов

`make route-setup` один раз устанавливает зависимости генератора в отдельное
окружение, `make route` пересобирает карту Русской тропы из локального кэша.
Для другой записи: `make route ROUTE=slug`. Подробности и ограничения —
[tools/route-generator/README.md](tools/route-generator/README.md).

GPX и OSM-кэш хранятся в `route-sources/`, вне публикуемых Hugo-каталогов.
Они не попадают в сайт, но остаются видимыми в исходниках репозитория.
Готовые `route.png` и `route.svg` лежат в ресурсах статьи; shortcode `route-map`
показывает адаптивное превью со ссылкой на полный размер и атрибуцией OSM.
Обычная сборка сайта не запускает генератор и не обращается к Overpass.

Текущие производные логотипа (Pillow, Python 3.11+):

```sh
python3 scripts/logo.py --hide tagline --trim-bottom --output assets/images/logo.png
python3 scripts/logo.py --hide wordmark tagline --trim --output assets/images/logo-illustration.png
python3 scripts/logo.py --hide tagline --social-base --output assets/images/social-paper.png
```

Рисунок и название берутся из неизменяемых слоёв v1. Подпись задана в
`hugo.toml` (`params.tagline`); в шапке она выводится HTML-текстом над описанием, справа от логотипа.
Правила отдельных OG-композиций главной и статей закреплены в
`docs/PROJECT-CONTEXT.md`, реализация — `layouts/partials/social-image.html`.
Основа social-paper.png — только непрозрачная бумага; слои и подписи
добавляет Hugo. Статьи используют social_image или cover, иначе только рисунок логотипа
без названия и подписи. На всех карточках статей сверху «Бродов нет»,
снизу строчное brodov.net;
Fit сохраняет изображение целиком.
Производные находятся в Hugo assets: URL логотипа получает fingerprint,
URL социальных карточек меняется при пересборке текста или основы.


## Солнечные календари

Страница `/sun-calendar/` и отдельные ICS для 52 городов. Исходники в отдельном
репозитории https://github.com/samael500/sun-calendar, подключённом как submodule
`vendor/sun-calendar`. `make` генерирует файлы в игнорируемый `static/sun-calendar/`
перед Hugo. Календари охватывают 6 месяцев назад и 6 вперёд; даты пересчитываются
при каждой сборке в часовом поясе города. Данные/карта/шрифты локальные.

Обновление кода генератора: поменять commit submodule на dev, проверить `make check`,
провести PR/review. Ежедневная сборка не подтягивает непроверенный main генератора.
GitHub может отключить schedule после 60 дней отсутствия активности; при этом
последняя версия календарей остаётся доступной. Проверяйте Actions, при необходимости
включайте workflow снова. Старую московскую подписку надо заменить новой ссылкой:
`https://brodov.net/sun-calendar/moscow.ics`.
