# Контекст проекта «Бродов нет»

Этот документ хранит устойчивые решения для следующих сессий работы. Текущий код и опубликованный Markdown остаются источником истины; временные handoff и макеты не заменяют репозиторий.

## Назначение и характер

«Бродов нет» — личный бортовой журнал Максима Скорохода о жизни: трейлах, лесах и болотах, путешествиях, семье и быте, рецептах, пайке, Arduino, играх, мультфильмах и экспериментах с изображениями. Это не профессиональная витрина тимлида и не тематический кулинарный сайт.

Название — шутка трейлраннера, который постоянно оказывается в бродах. Тон уютный и спокойный, но допускает грязь, самоиронию и неидеальность жизни.

- Название: «Бродов нет».
- Подзаголовок: «Бортовой журнал».
- Описание: «Истории из лесов и болот, заметки с кухни и рабочего стола. Всё начинается с мысли: “А почему бы и да…”»
- Production: <https://brodov.net/>.

## Принятые технические решения

- Hugo; публикации хранятся в Markdown и Git как page bundles.
- Репозиторий: `samael500/brodov.net`. Старый `maks.live` и его репозиторий не изменять в рамках работы над этим сайтом.
- Canonical URL, description, Open Graph, Twitter Card, JSON-LD, RSS и sitemap должны сохраняться при изменениях оформления и контента.
- `check.yml` проверяет каждый push и pull request. `deploy.yml` публикует GitHub Pages только вручную; push и deploy — отдельные действия.
- Browser CMS не нужна. Комментарии и аналитика пока не подключены.

Обычный цикл: обсуждение или черновик → изменение файлов по поручению → preview → проверка → коммит → push и публикация только по явному поручению. Случайная мысль в обсуждении сама по себе не означает правку статьи.

## Визуальная система

- Основной текст и заголовки — Literata; навигация, даты, служебный текст и подписи — PT Sans. Шрифты хранятся локально вместе с лицензиями.
- Цвет текста — `#35312F`, фон — `#FAF8F3`, вторичный текст — `#6A625B`, разделители — тёплые нейтральные около `#D6D0C7`.
- Бумажная фактура `static/images/paper-grain.png` повторяется с opacity `0.055` отдельным слоем под содержимым и не перехватывает события.
- Основная колонка статьи — не шире 660 px; текст 20 px/1.6, на мобильном 18 px. Избегать ярких акцентов, виньеток и декоративного «пергамента».
- Превью записи задаётся через `preview_image` и `preview_image_alt` в front matter. Записи без изображения должны сохранять полноценный текстовый вид.

### Логотип

Утверждённый логотип — фиксированный мастер, а не prompt для генерации. `design/logo-master/` — неизменяемая версия v1 с контрольными суммами. Для детерминированных производных использовать `scripts/logo.py`; не отправлять мастер генератору, не реконструировать и не перерисовывать его по памяти. Подробные защитные правила находятся в корневом `AGENTS.md`.

## Редакторские принципы

Сохранять авторский живой рассказ: последовательность событий, конкретные бытовые детали, короткие фразы рядом с длинными, повторы, самоиронию и искренние впечатления. При редактуре улучшать ясность и исправлять ошибки, но не обезличивать текст и не превращать его целиком в телеграфный стиль.

Не выдумывать переживания, диалоги, погоду, события и воспоминания. Не добавлять банальную мораль или натужную уютность. Новые факты получать от автора либо из проверяемых источников. Не делать работу с ИИ центром текста, если это не тема самой публикации.

Опубликованный Markdown приоритетнее старых макетов и handoff. Статья «Квадратная пицца по рецепту из детства» опубликована по `/posts/pizza/` с датой 2026-09-13; её текст, дата, URL, метаданные и четыре утверждённые иллюстрации не меняются в рамках оформления.

## Иллюстрации еды

Утверждённая серия напоминает современную кулинарную книгу: мягкая акварель, цветной карандаш, тонкая штриховка, спокойные тёплые цвета и естественные пропорции. Без фотореализма, 3D, рекламного глянца, мультяшности и лишних декоративных ингредиентов.

Исходная фотография — источник истины для формы блюда, толщины, начинки, подрумянивания и фактуры. Для новых работ использовать фото блюда и один зафиксированный утверждённый рисунок как стилевой якорь. Существующие утверждённые изображения не перегенерировать ради CSS-правок. Кулинарный `mix-blend-mode: multiply` должен быть ограничен их классом и не применяться к логотипу, фотографиям и social cards.

## Открытые вопросы

- Перенос старых статей и редиректы с `maks.live`.
- Нужны ли комментарии и какой механизм выбрать.
- Поведение анонсов будущих записей без изображения и с фотографиями на реальных материалах.
- Более удобный постоянный preview/publish процесс поверх текущего workflow.
- Recipe JSON-LD — только после появления достоверных структурированных данных; не выдумывать массы, время, калории и порции.
