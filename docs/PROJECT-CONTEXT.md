# Контекст проекта «Бродов нет»

Этот документ хранит устойчивые решения для следующих сессий работы. Текущий код и опубликованный Markdown остаются источником истины; временные handoff и макеты не заменяют репозиторий.

## Назначение и характер

«Бродов нет» — личный журнал Максима Скорохода о жизни: трейлах, лесах и болотах, путешествиях, семье и быте, рецептах, пайке, Arduino, играх, мультфильмах и экспериментах с изображениями. Это не профессиональная витрина тимлида и не тематический кулинарный сайт.

Название — шутка трейлраннера, который постоянно оказывается в бродах. Тон уютный и спокойный, но допускает грязь, самоиронию и неидеальность жизни.

- Название: «Бродов нет».
- Подзаголовок: «Журнал обыкновенных невероятностей» (утверждён 20.09.2026).
- Описание: «Истории из лесов и болот, заметки с кухни и рабочего стола. Всё начинается с мысли: “А почему бы и да…”»
- Production: <https://brodov.net/>.

## Принятые технические решения

- Hugo; публикации хранятся в Markdown и Git как page bundles.
- Репозиторий: `samael500/brodov.net`. Старый `maks.live` и его репозиторий не изменять в рамках работы над этим сайтом.
- Canonical URL, description, Open Graph, Twitter Card, JSON-LD, RSS и sitemap должны сохраняться при изменениях оформления и контента.
- `check.yml` проверяет каждый push и pull request. `deploy.yml` публикует GitHub Pages только вручную; push и deploy — отдельные действия.
- Browser CMS не нужна. Комментарии и аналитика пока не подключены.

Порядок работы с 21.09.2026: обсуждение или черновик → изменения в `dev` →
preview → проверки → коммит → push `dev` → pull request `dev` → `main` →
ревью владельца → слияние после его явного одобрения → публикация.
Все новые изменения вести в `dev`. Прямые коммиты/push в `main` и обход PR
запрещены. Основная ветка сейчас называется `main` (в поручении автора —
«master»); без отдельного запроса её не переименовывать. Поручение «публикуем»
означает подготовку PR, а не разрешение пропустить ревью. Deploy выполнять
только из основной ветки после одобренного слияния, не из `dev`.
Случайная мысль в обсуждении сама по себе не означает правку статьи.

## Визуальная система

- Основной текст и заголовки — Literata; навигация, даты, служебный текст и подписи — PT Sans. Шрифты хранятся локально вместе с лицензиями.
- Цвет текста — `#35312F`, фон — `#FAF8F3`, вторичный текст — `#6A625B`, разделители — тёплые нейтральные около `#D6D0C7`.
- Бумажная фактура `static/images/paper-grain.png` повторяется с opacity `0.018` отдельным слоем под содержимым и не перехватывает события.
- Основная колонка статьи — не шире 660 px; текст 20 px/1.6, на мобильном 18 px. Избегать ярких акцентов, виньеток и декоративного «пергамента».
- Изображение анонса выбирается отдельно от фотографий и обложки статьи через `preview_image` и `preview_image_alt`. На главной это компактная картинка рядом с текстом (на узком экране — над текстом), высотой не более 260 px без обрезки. Если подходящего изображения нет, оставлять полноценный текстовый анонс; автоматически брать первую фотографию не нужно.
- Для анонса «Русской тропы» используется отдельная карта: маршрут с подложкой, без заголовка, подписей точек и профиля высоты. Атрибуция OSM сохранена. Портрет остаётся внутри рассказа.

### Логотип

Утверждённый логотип — фиксированный мастер, а не prompt для генерации. `design/logo-master/` — неизменяемая версия v1 с контрольными суммами. Для детерминированных производных использовать `scripts/logo.py`; не отправлять мастер генератору, не реконструировать и не перерисовывать его по памяти. Подробные защитные правила находятся в корневом `AGENTS.md`.

## Редакторские принципы

Сохранять авторский живой рассказ: последовательность событий, конкретные бытовые детали, короткие фразы рядом с длинными, повторы, самоиронию и искренние впечатления. При редактуре улучшать ясность и исправлять ошибки, но не обезличивать текст и не превращать его целиком в телеграфный стиль.

Не выдумывать переживания, диалоги, погоду, события и воспоминания. Не добавлять банальную мораль или натужную уютность. Новые факты получать от автора либо из проверяемых источников. Не делать работу с ИИ центром текста, если это не тема самой публикации.

Опубликованный Markdown приоритетнее старых макетов и handoff. Статья «Квадратная пицца по рецепту из детства» опубликована по `/posts/pizza/` с датой 2026-09-13; её текст, дата, URL, метаданные и четыре утверждённые иллюстрации не меняются в рамках оформления.

## Иллюстрации еды

Утверждённая серия напоминает современную кулинарную книгу: мягкая акварель, цветной карандаш, тонкая штриховка, спокойные тёплые цвета и естественные пропорции. Без фотореализма, 3D, рекламного глянца, мультяшности и лишних декоративных ингредиентов.

Исходная фотография — источник истины для формы блюда, толщины, начинки, подрумянивания и фактуры. Для новых работ использовать фото блюда и один зафиксированный утверждённый рисунок как стилевой якорь. Существующие утверждённые изображения не перегенерировать ради CSS-правок. Кулинарный `mix-blend-mode: multiply` должен быть ограничен их классом и не применяться к логотипу, фотографиям и social cards.

## Карты маршрутов — утверждённые правила

Утверждено автором 17.09.2026 на примере «Русской тропы», включая миниатюру
с утолщённым маршрутом. Использовать как образец для следующих статей.
Одобрение оформления не означает разрешение на публикацию.

### Общий вид

- Геометрия маршрута — из GPX, подложка — из OpenStreetMap; не дорисовывать географию нейросетью.
- Светлая бумага `#FAF8F3`, приглушённые поля, луга, леса и вода. Подложка плавно растворяется по краям; трек остаётся чётким, целиком в кадре, без искажения пропорций.
- Маршрут тёплый терракотовый `#A6533D`, основной текст `#35312F`, служебные подписи `#82796D`. Заголовок — локальная Literata, подписи — локальный PT Sans.
- В карту не добавлять зерно. Фактура страницы едва заметная: opacity `0.018`.
- Сохранять атрибуцию OpenStreetMap. На полной карте — также адрес openstreetmap.org/copyright, в статье — кликабельная ссылка на атрибуцию.

### Полная карта в статье

- Заголовок и подзаголовок с местом, датой забега, официальной дистанцией и результатом; ниже карта и профиль высоты.
- Толщина маршрута — `1.8 pt` в Matplotlib. Сохранять отметки дистанции (для Русской тропы через 20 км), старт/финиш, масштаб и подписи населённых пунктов. Шаг отметок для другого трека выбирать по его длине и читаемости.
- Без указателя севера, специального маркера глубокого брода, стрелки на профиле, легенды цветов и фразы «Исходный GPX сохранён».
- Недостоверные высоты задавать отдельными интервалами в конфиге конкретного трека. Пунктир соединяет соседние доступные значения, не восстанавливает рельеф; пояснение обязательно. Не переносить интервалы Русской тропы в другие маршруты.
- Различать официальную дистанцию и расстояние по GPS; не выдумывать набор высоты или другие показатели.
- Вставлять карту по смыслу рассказа рядом с описанием дистанции. Для Русской тропы утверждено место после абзаца о разметке. Адаптивное превью открывает полный SVG; рядом доступен PNG.
- Фотографии остаются частью рассказа: карта не требует заменять их иллюстрациями.

### Миниатюра для главной

- Отдельный файл `route-preview.png`: только маршрут с подложкой и атрибуцией OSM. Без заголовка, подзаголовка, профиля высоты, отметок километров, маркеров старта/финиша, масштаба и мелких подписей населённых пунктов.
- Для миниатюры линия толще: `2.5 pt` вместо `1.8 pt`. Менять её независимо от полной карты, сохраняя цвет и геометрию.
- Компактная картинка рядом с текстом, на узком экране — над текстом; высота не более 260 px, без обрезки маршрута. Мягкие края сочетаются с фоном страницы.
- Выбирать анонс отдельно через `preview_image` и `preview_image_alt`; вертикальный портрет не подставлять автоматически. Если подходящей картинки нет, текстовый анонс допустим.

### Генерация и проверка

Генератор `tools/route-generator/` строит статичные PNG/SVG по GPX и кэшу OSM.
Исходники находятся в `route-sources/`, готовые карты — в page bundle статьи.
`make route` работает офлайн; для другой статьи — `make route ROUTE=slug`.
Миниатюра создаётся вместе с полной картой, если задан `preview_output` в JSON.
Обычная сборка Hugo использует готовые картинки и не обращается к Overpass.

GPX с персональными показаниями не публикуется на сайте; публичный Git при этом
открывает исходники. Ссылку на скачивание GPX добавлять только по просьбе автора.

Для каждого нового маршрута проверять подписи и их пересечения, читаемость трека
в миниатюре, сохранность всего маршрута, атрибуцию, вид статьи и главной на desktop
и mobile. Универсальное устранение коллизий подписей не реализовано. Перед
публикацией показывать предпросмотр автору; изменения вести через `dev` и PR
с ревью владельца, согласно порядку работы выше.
