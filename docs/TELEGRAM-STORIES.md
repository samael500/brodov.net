# Собственные Telegram Stories → черновики

Экспортёр работает только с аккаунтом, в который автор вошёл локально.
Все запросы Stories используют `peer='me'`. Просмотрщики, переписки и
контакты не запрашиваются. Версии: Telethon 1.45.0, Pillow 11.3.0,
PyYAML 6.0.2; закреплены в `tools/requirements-stories.txt`.
Для производных видео нужны системные `ffmpeg` и `ffprobe`.

## Экспорт Telegram Desktop без API-ключей

В Telegram Desktop: Настройки → Продвинутые настройки → Экспорт данных →
Архив историй, фотографии и видео; формат HTML + JSON. JSON нужен для точных
дат, HTML — для подписей: JSON-экспорт Telegram Desktop их пропускает. Затем:

```sh
./tools/.stories-venv/bin/python tools/telegram_stories.py desktop \
  --input '/путь/к/DataExport_YYYY-MM-DD'
```

Команда копирует оригиналы без пересжатия в отдельный приватный
`../.brodov-private/telegram/desktop-archive/`, проверяет SHA-256 и создаёт
`review.html`. Исходный экспорт не изменяется. При повторе дата UTC из
`date_unixtime` и хэш медиа позволяют узнать тот же кадр даже после изменения
нумерации файлов. Изменённое медиа сохраняется отдельно; исчезнувшие кадры
не удаляются. Копируется только раздел stories, не переписки и контакты.

Desktop не предоставляет ID истории/владельца и аудиторию: `pinned` не
означает публичность. Автоматического объединения с API-архивом нет.
Если рядом есть `lists/stories.html`, подписи извлекаются из него без исполнения
HTML/JavaScript. Сохраняются переносы, хештеги и адреса ссылок. Сопоставление —
по уникальной дате внутри того же экспорта с проверкой ссылки на медиа. При
пропущенном из-за размера медиа допускается единственная сохранённая история
с той же UTC-датой и проверенным SHA-256. Неоднозначность останавливает импорт.
Повторный JSON без подписей не стирает ранее извлечённый текст.
Отдельные подписи могут отсутствовать; текст внутри картинки остаётся частью
изображения и автоматически не распознаётся. Полнота проверяется относительно
JSON, а не аккаунта Telegram. Недостающие файлы видны в review и не выбираются.

После отбора:

```sh
./tools/.stories-venv/bin/python tools/telegram_stories.py import \
  --input ../.brodov-private/telegram/desktop-archive \
  --selection /путь/к/selection.json --drafts
```

19.09.2026 проверен реальный экспорт автора: 126/126 файлов, 111 JPG и
15 MP4, 201664573 байта. Все копии совпали по SHA-256; изображения читаются,
видео распознаются ffprobe. Во всех 126 записях отдельные подписи отсутствуют.
Время Unix используется как источник даты; группировка блога — Europe/Moscow.
Архив подготовлен к отбору, реальные черновики ещё не созданы.

## Первый вход и пробная выгрузка

1. Самостоятельно открыть <https://my.telegram.org>, API development tools,
   создать собственное приложение, получить `api_id` и `api_hash`.
2. В локальном терминале:

```sh
cd /home/mskorokhod/life/brodov.net
make stories-setup
./tools/.stories-venv/bin/python tools/telegram_stories.py export --limit 3
```

Команда интерактивно спросит API ID, API hash, телефон, код Telegram и,
если требуется, 2FA. API hash, код и пароль вводятся скрыто. Ничего из этого
не присылать в чат и не вписывать аргументами командной строки.
После входа будет показано имя/username; владелец подтверждается локально.
Дальнейшие запуски сверяют сохранённый числовой ID владельца.

Сессия и ключи сохраняются вне Git в
`/home/mskorokhod/life/.brodov-private/telegram/` (папка 0700, файлы 0600).
Не копировать эту папку в репозиторий или публичные архивы.
Исключения для session/session-journal/wal/shm и .env добавлены в .gitignore.
Пример формы конфигурации — `tools/stories/app.example.json`; его не нужно
заполнять в Git, интерактивная команда сама создаёт приватный `app.json`.

Первые три истории нужны для smoke test. Число 126 из старого скриншота
не является ожидаемым гарантированным итогом. После проверки образцов:

```sh
./tools/.stories-venv/bin/python tools/telegram_stories.py export --all
```

Выгружаются архив, закреплённые и активные истории; объединение по
owner_id/story_id. Статус каждого источника выводится отдельно; limited,
unavailable и stopped_no_progress не означают «скачано всё».
Утраченное в Telegram медиа восстановить не обещаем. Исходная Telegram-
версия — не обязательно оригинал камеры.

Во время FloodWait клиент ждёт указанный сервером срок. Ctrl+C безопасен;
повторная команда продолжает по manifest. Прерывание скачивания оставляет
.part, при повторе оно скачивается заново. Готовность ставится после
успешной загрузки, SHA-256 и атомарного переименования. При изменении
медиа прежний оригинал не перезаписывается. Удаление источника не удаляет
локальные оригиналы или записи блога. Истёкший file reference обновляется
с ограниченным повтором. Ошибки отдельных кадров видны в review.

## Отбор

Архив по умолчанию:
`/home/mskorokhod/life/.brodov-private/telegram/archive/`.
Внутри manifest, `stories/<owner>-<story>/source.json`, версии metadata,
исходные медиа и `review.html`. Исходные даты UTC, подписи, entities,
аудитория, размеры, хэши сохраняются отдельно от блоговой редакции.

```sh
./tools/.stories-venv/bin/python tools/telegram_stories.py review
```

Открыть выведенный `review.html` в браузере. Отметить кадры, при необходимости
задать одинаковую группу и порядок для одного сюжета. Близость времени сама
по себе не объединяет истории. Указать заголовок и alt. Кнопка «Скачать
selection.json» сохраняет только выбор, ничего не публикует. Перенести
скачанный файл в приватный архив или передать его путь команде импорта.

```sh
./tools/.stories-venv/bin/python tools/telegram_stories.py import \
  --selection /путь/к/selection.json --drafts
make preview
```

Импорт создаёт **новые draft:true**, никогда не публикует и не перезаписывает
существующий Markdown. Привязки кадров и source_hash хранятся в приватном
`imports.json`, не в HTML. Изменившаяся исходная подпись отмечается в review.
При изменении группировки уже импортированных кадров инструмент останавливается,
чтобы не создать дубли и не потерять редактуру; объединение нужно править явно.

Кадры: EXIF-ориентация, sRGB при наличии профиля, максимум 1600px без апскейла,
без EXIF GPS. Исходники неизменны. Встроенные даты/стикеры не стираются.
Видео преобразуется в H.264/AAC MP4 с poster. Ошибка преобразования оставляет
архив целым и не создаёт неполную историю. Подписи — plain text с сохранением
ссылок text_url, никакого доверенного HTML. Тег #цветыикроссовки сохраняется.
Автоматический заголовок при отсутствии заданного — лишь fallback из подписи;
перед публикацией проверить название, alt, crop и порядок кадров в черновике.

GetStoriesByIDRequest. До локального входа автора реальные аккаунт и выгрузка
**не проверены**. Офлайн-тесты подменяют только транспорт.

- [stories.getPinnedStories](https://core.telegram.org/method/stories.getPinnedStories)
- [stories.getPeerStories](https://core.telegram.org/method/stories.getPeerStories)
- [API ID](https://core.telegram.org/api/obtaining_api_id)
- [Telethon: вход](https://docs.telethon.dev/en/stable/basic/signing-in.html)
- [Telethon: сессии](https://docs.telethon.dev/en/stable/concepts/sessions.html)

19.09.2026 второй экспорт `DataExport_2026-09-19 (1)` содержал HTML + JSON:
подписи сопоставлены для всех 126 записей, непустых — 27. Десять видео в новой
выгрузке пропущены лимитом размера; использованы проверенные копии из первой.
Архив по-прежнему содержит 126 полных историй без дублей. Review обновлён,
редакторские черновики не создавались. Проверки unittest: 25 прошли.
