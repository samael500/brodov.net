# Интеграция генератора карт в brodov.net

Интеграция выполнена. Актуальные утверждённые правила, включая отдельную миниатюру и её толщину линии, сохранены в [контексте проекта](../../docs/PROJECT-CONTEXT.md#карты-маршрутов--утверждённые-правила). Ниже — исходное задание на интеграцию.

Пользователь утвердил внешний вид russian-trail-map-v9: приглушённые поля/луга/леса, светлая бумага #FAF8F3, тёплый маршрут, края подложки плавно исчезают. Без указателя севера, маркера глубокого брода, стрелки на профиле, легенды цветов и фразы «Исходный GPX сохранён». Остаются отметки через 20 км, старт/финиш, масштаб, атрибуция OSM и сноска к пунктиру профиля. Зерно сейчас не добавлять.

Этот пакет обобщает тот рисунок: title/subtitle/GPX/кэш/шаг отметок/пропуски высоты вынесены в JSON. Полный пример Русской тропы прилагается. Небольшие отличия профиля от эскиза ожидаемы: пределы оси теперь выбираются по данным, пунктир связывает соседние доступные точки.

1. Прочитать AGENTS.md текущего репозитория, проверить status/remote и структуру. Сохранить чужие изменения.
2. Поместить утилиту в подходящее место scripts/ или tools/; пример связать с существующей статьёй /posts/russian-trail/. Не менять текст, дату и URL статьи.
3. Выбрать размещение GPX/кэша в исходниках: по умолчанию вне Hugo static/page bundle, чтобы персональные исходники с пульсом не публиковались автоматически. Это не запрет публикации GPX — ссылку на скачивание можно добавить отдельно по просьбе автора. Готовые route.png/svg положить в ресурсы статьи.
4. Использовать локальную Literata и при необходимости PT Sans из проекта, сохранив лицензии. Не генерировать логотип и не менять айдентику.
5. Добавить простую команду для автора; обычная сборка сайта должна использовать готовую картинку и работать без Overpass. Кэш позволяет пересобирать картинку офлайн. Не привязывать генерацию к внешнему API на каждом push.
6. Вставить карту в подходящее место статьи вместо старого скриншота Suunto, сохранив остальные фото. Учесть, что изображение высокое: предпросмотр в статье + открытие полного размера. Согласовать placement в контексте текущей задачи, если пользователь просит только установить утилиту.
7. На новом треке проверить подписи визуально: универсальное устранение коллизий пока не реализовано. Не обещать идеальную вёрстку любого маршрута.
8. Проверить сборку Hugo, mobile/desktop, видимость подписей и атрибуцию. Работа с Git/публикацией — согласно текущему поручению пользователя, без самовольного push.

Проверено при подготовке: GPX Русской тропы (40366 точек) → офлайн PNG/SVG; расстояние 112.601 км. Кэш соответствует исходному GPX. Реальный сетевой импорт геоданных выполнен при подготовке эскизов, обобщённый --fetch отдельно на новом треке ещё не проверен.

Следующие улучшения по необходимости: коллизии подписей; несколько трек-сегментов; компактная горизонтальная композиция; связи карты с фотографиями/текстом; интерактивная карта. Не добавлять их автоматически в первый коммит.
